## 1. 문제 정의와 좌표계

**목표**: 영상 좌표 (line ℓ, sample s) 와 지상 좌표 (φ, λ, h) 사이의 양방향 사상을 세움.

**좌표계**
- 지상점 P, 위성 위치 S, 속도 V 는 모두 **ECEF** (지구고정 직교좌표, WGS84). 헤더의 상태벡터가 이미 ECEF 이므로
  관성좌표(ECI) 회전이 필요 없음. 확인: 위치의 유한차분 dP/dt 와 헤더 속도 V 의 잔차 rms 0.81 m/s
  (ECI 였다면 지구자전 ω×r ≈ 500 m/s 차이).
- 지리좌표 ↔ ECEF (`geometry.geodetic_to_ecef / ecef_to_geodetic`): a = 6378137, f = 1/298.257223563.
  ```
  N = a / sqrt(1 − e² sin²φ)
  x = (N+h) cosφ cosλ,  y = (N+h) cosφ sinλ,  z = (N(1−e²)+h) sinφ
  ```
  역변환은 φ 를 반복 (`φ ← atan2(z, p(1 − e²N/(N+h)))`, 1e-12 rad 수렴).
- 지도 출력은 EPSG:32652 (UTM 52N), pyproj 로 변환.

**높이**: 모델의 h 는 **타원체고**. DEM(Copernicus, EGM2008 정표고) 에는 지오이드고 N ≈ +26.0 m 를 더함.

## 2. 영상 격자 ↔ (t, R) — 모델의 뼈대

헤더 값 (SBI 속성) 에서:

```
t(ℓ) = t0 + ℓ·Δt              t0 = Zero Doppler Azimuth First Time  (UNIX 초)
                              Δt = Line Time Interval = 1/PRF        (156.92 μs)
R(s) = R0 + s·ΔR              R0 = c·τ0/2,  τ0 = Zero Doppler Range First Time (왕복 초)
                              ΔR = c·Δτ/2,  Δτ = Column Time Interval
```
20250611: t0 = 1749591380.234173, R0 = 591 842.6 m, ΔR = 0.9993 m (96.8 MHz 모드; 48.4 MHz 모드는 2.0 m).

두 가지 함정:
- τ 는 **왕복** 시간임. ÷2 를 빼면 R0 가 1184 km 가 되어 H/cos(look)=590 km 와 어긋나므로 바로 드러남.
- LV1A 는 스트립 앞 절반만 담지만 t0·Δt·`Line Samples` 는 전체 스트립 기준임. 격자는 헤더대로 세우고
  데이터 존재 범위 `n_avail = SBI.shape[0]//2` 만 따로 관리한다 (§README 2-1).

편향 보정은 이 두 식의 원점만 건드린다 (§10):
```
t_eff(ℓ) = t0 + Δt_bias + ℓ·Δt
R_eff(s) = R0 + ΔR_bias + s·ΔR
```

## 3. 궤도 보간

**입력**: 상태벡터 60점, 1 s 간격, 씬 시작 −30 s ~ 끝 +21.5 s. 값은 float64 로 저장됐지만 실제로는 float32 로
양자화되어 있다 (예 `-3304971.5`, `3464.068359375`) → 위치 0.25~0.5 m 계단.

**방법** (`orbit.Orbit`): 시간을 씬 중앙 `t_ref` 기준으로 옮긴 뒤 (`x = t − t_ref`; 1.7×10⁹ 를 그대로 쓰면
5차에서 정규방정식 조건수가 폭발) 위치 xyz 각 성분을 `numpy.polynomial.Polynomial.fit(x, p, deg)` 로 적합.
속도·가속도는 다항식 도함수.

**차수 선택**: 4~9차 모두 적합잔차 0.31~0.38 m 로 차이가 없었다 — 양자화 잡음이 바닥. LOO(한 점 빼고 예측)는
4차 0.73 m 가 최소, 8차 이상은 1.1~1.3 m 로 악화. → **4차 채택**. 저차 다항식이 양자화 잡음을 평활하는 효과가 있음.
씬 길이 7.5 s 동안 궤도는 거의 등속·등가속이라 4차로 충분함.

**검증**: 위치다항 도함수 vs 헤더 속도 rms 0.07 m/s. |S|−6371 km = 510 km, |V| = 7.688 km/s.

## 4. 세 방정식과 해의 구조

지상점 P 가 픽셀 (t, R) 에 찍힌다는 것은:

```
①  |P − S(t)| = R                 거리:   P 는 S(t) 중심 반경 R 의 구 위
②  (P − S(t)) · V(t) = 0          도플러: 시선이 속도에 직각 (제로도플러 처리 영상)
③  (Px²+Py²)/(a+h)² + Pz²/(b+h)² = 1     지표: 타원체를 h 만큼 부풀린 면 위
```

기하학적 해석: ①∩② 는 위성 속도에 수직인 평면 위의 **원**임. 그 원이 ③ 과 만나는 점은 **둘**(위성 좌우) —
그래서 룩사이드가 필요함. ③ 대신 DEM 을 쓰면 h 가 P 에 의존하므로 반복이 필요하다 (§6).

왜 도플러중심 f_DC 가 0 인가: 헤더 `Doppler Centroid = −122.6 Hz` 는 원자료의 도플러 중심이고, 영상은 처리 과정에서
제로도플러 시각으로 재배열되어 있다 (`Zero Doppler Azimuth First Time` 이라는 이름이 그 뜻). 따라서 ② 는 f_DC = 0.

왜 자세각이 안 쓰이는가: Roll/Pitch/Yaw 는 안테나가 어디를 향했는지를 말하지만, 에코의 거리와 시각은 안테나 방향과
무관함. 포커싱이 끝난 SLC 의 기하는 ①②③ 로 완결됨.

## 5. geo2rdr (지상 → 영상) 알고리즘

지상점 P (ECEF) 가 주어졌을 때 (ℓ, s) 를 찾음. **①②만** 필요하고 룩사이드는 필요 없다 — 위성이 P 의
정면을 지나는 순간은 좌우 무관하게 하나뿐임.

```
g(t) = (P − S(t)) · V(t)                  ← 0 이 되는 t 를 찾는다
g′(t) = −|V(t)|² + (P − S(t)) · A(t)      ← A = 가속도 (생략해도 수렴하지만 넣으면 2회 빨라짐)

t ← t_mid                                 초기값: 씬 중앙시각
repeat: t ← t − g(t)/g′(t)  until |Δt| < 1e-9 s     (보통 3~4회)
R = |P − S(t)| (+ 대류권 지연, §9)
ℓ = (t − t0 − Δt_bias)/Δt,   s = (R − R0 − ΔR_bias)/ΔR
```
`geometry.RangeDoppler.geo2rdr(P)` 는 P 의 배열 `(…,3)` 을 받아 전부 벡터화함. 2.4M 점(DEM 블록) 에
20회 반복해도 수 초.

수렴성: g(t) 는 t 에 대해 거의 선형(−|V|²·(t−t*) 지배, |V|² ≈ 5.9×10⁷) 이라 뉴턴이 실패할 여지가 없음.
1e-9 s 는 방위 6×10⁻⁶ px.

## 6. rdr2geo (영상 → 지상) 알고리즘

(ℓ, s, h) 가 주어졌을 때 P 를 찾음. 3D 뉴턴 대신 **미지수를 룩각 θ 하나로** 줄임.

**위성 좌표계** (`_frame(t)`):
```
v̂ = V/|V|                                  진행 방향
n̂ = unit( −S − (−S·v̂) v̂ )                 "아래" (지구중심 방향에서 진행 성분을 뺀 것, ⊥ v̂)
ĉ_right = n̂ × v̂                            "오른쓸"
```
`ĉ_right` 의 방향 확인: 동쪽으로 진행(v̂ = +x)하며 아래가 −z 이면 (−z) × x = −y = 남쪽 = 오른쪽 ✓.

**시선 벡터의 1모수 표현**: ② 를 만족하는 시선은 v̂ 에 수직인 평면 안에 있으므로
```
û(θ) = cosθ · n̂ + s · sinθ · ĉ_right         s = +1 우측룩, −1 좌측룩
P(θ) = S + R · û(θ)                          ← ① 자동 만족
```
남는 것은 ③ 하나:
```
f(θ) = (Px²+Py²)/(a+h)² + Pz²/(b+h)² − 1
f′(θ) = ∇f · dP/dθ,   dP/dθ = R(−sinθ n̂ + s cosθ ĉ_right),   ∇f = (2Px/(a+h)², 2Py/(a+h)², 2Pz/(b+h)²)
θ ← |Look Angle| (헤더, 30.16°)            초기값
repeat: θ ← θ − f/f′  until |Δθ| < 1e-12 rad
```
`_solve_theta()` 가 이것이고, 배열 입력 전부 벡터화. 1e-12 rad × 590 km = 6×10⁻⁷ m.

**DEM 위의 점** (`rdr2geo_dem`): h 는 P 에 의존하므로
```
h ← 0 (또는 초기값)
repeat: P = rdr2geo(ℓ, s, h);  (φ,λ) = ecef_to_geodetic(P);  h_new = DEM_ellip(φ,λ)
until |h_new − h| < 0.01 m  (평지 2~3회, 급사면 5~10회)
```
한라산 1950 m 에서 h=0 으로 풀면 지상거리 방향으로 h/tan(inc) ≈ 3.1 km 틀린다 — 반복 필수.

**대류권 (`tropo=True`)**: 측정 R 은 기하 R 보다 지연만큼 길어짐. 지연은 P 의 높이·입사각에 약하게 의존하므로
h 로 먼저 한 번 풀어 P₀ 를 얻고, `R ← R − delay(P₀)` 후 다시 푼다 (1회 선행으로 충분: 지연 변화 < 1 cm).

## 7. 룩사이드 판별

```
side_of(P, t) = sign( (P − S(t)) · ĉ_right(t) )        +1 오른쪽, −1 왼쪽
```
백록담을 넣으면 +1 = 헤더 `Look Side = RIGHT` 와 일치. 일부러 s 를 뒤집어 풀면 P 가 120.35°E, 592 km
서쪽 바다에 떨어진다 — 부호 실수는 즉시 드러나는 구조임. 헤더 `Look Angle` 부호(음수 우측)와도 일치.

## 9. 대류권 지연 모델 (`tropo.py`)

전파는 대기에서 진공보다 느리므로 측정 거리가 길어진다: `R_meas = R_geom + d`.

```
P(h) = 1013.25 · (1 − 2.2558e-5·h)^5.2559            표준대기 기압 [hPa]
ZHD  = 0.0022768 · P(h) / (1 − 0.00266 cos2φ − 0.00028 h_km)      Saastamoinen 건조항
ZWD  = 0.15 · exp(−h/2000)                              습윤항 근사 (해면 0.15 m)
d    = (ZHD + ZWD) / cos(inc)                           슬랜트 (inc < 40° 에서 1/cos 매핑 충분)
```
해면 2.92 m, 1000 m 2.54 m, 정상부(1950 m) 2.23 m @32.6°. 실제 기상 대비 ±0.2 m — 궤도 양자화 0.5 m 가
바닥이므로 ERA5 적분은 과잉임. 바꾸려면 `zenith_delay()` 만 교체.

모델에 넣는 위치: `geo2rdr` 는 R_geom 에 d 를 **더해** 측정 격자로, `rdr2geo` 는 측정 R 에서 d 를 **빼고** 기하를 풂.
따라서 추정된 ΔR_bias 는 "대류권을 뺀 뒤의 계기 편향"임. 단 SaTReC 처리기가 이미 대류권을 보정했는지는 알 수 없어
순수 계기값은 30~32 m 범위로 해석함.

## 10. 편향 모델과 추정 — DEM 시뮬레이션 정합

### 10-1. 왜 2모수 상수인가
처리기가 남기는 계통오차는 (a) 거리 원점(내부 전자지연·시각 동기) 과 (b) 방위 시각 태깅임. 둘 다 씬 안에서 상수이고
위성 고유값임. 그래서 편향을 격자 원점 두 개 `(Δt_bias, ΔR_bias)` 로 두고, 위치의존(선형항)은 **검정으로** 확인함.
궤도 3모수(along/cross/radial) 표현은 스와스 안 입사각 폭이 0.9° 라 cross↔radial 이 분리되지 않아 2모수와 동치.

### 10-2. 시뮬레이션 (`simulate.simulate`)
DEM 블록(15 m 오버샘플) 의 면요소마다:
```
P = ECEF(φ, λ, h_ell)
(t, R, ℓ, s) = geo2rdr(P)
los = unit(S(t) − P)                        지표 → 위성
cosθ_loc = n_ecef · los                     국지입사각의 cos (n = 경사면 단위법선)
w = area · max(cosθ_loc, 0)                 레이더가 보는 투영면적
bin(⌊ℓ/b_l⌋, ⌊s/b_s⌋) += w                  np.bincount 누적
```
- 위성을 향한 급사면 (θ_loc 작음) → 밝음. 등돌린 면 → 0.
- 여러 면요소가 한 빈에 겹치면 (레이오버) 자연히 밝아짐 — 실영상의 레이오버 밝기와 같은 물리.
- 차폐(그림자)는 계산 안 함: 32° 입사에서 58° 이상 경사가 필요해 드묾.
- 면적 `area = dx·dy·sqrt(1 + (∂z/∂x)² + (∂z/∂y)²)`, 법선은 ENU (−∂z/∂e, −∂z/∂n, 1) 정규화 후 ECEF 로 회전.

### 10-3. 실영상 멀티룩 (`multilook_intensity`)
존재 라인 전체를 청크로 읽어 `I = mean(|z|²)` 를 (b_l × b_s) 빈으로. 강도(intensity) 평균이 스펙클에 대해 올바른
추정량이다 (진폭이나 dB 를 평균하면 편향). 캐시 `ml_<date>_<bl>x<bs>.npy`.

### 10-4. 정합 (`match`)
```
sim_dB = 10·log10(sim),  real_dB = 10·log10(I)
고역통과: x − gaussian_filter(x, σ),   σ = 120 m / (bin 지상크기)      ← 물리 스케일로 고정
마스크: sim > 0 & 빈 평균높이 > 30 m (바다·저지 제외) & real 유효
for (dl, ds) in 탐색격자:  r(dl, ds) = 마스크된 피어슨 상관( real(ℓ,s), sim(ℓ−dl, s−ds) )
피크 (i,j) 주변 5×5 에 2차곡면 z = c0 + c1x + c2y + c3x² + c4xy + c5y² 최소제곱 → 극대점 = 서브빈 위치
```
규약 `real(ℓ,s) ≈ sim(ℓ−dl, s−ds)`: 모델이 (ℓ,s) 에 놓은 지형이 실제로는 (ℓ+dl, s+ds) 에 있음.
편향 반영 `add_image_offset(dl, ds)`: `Δt_bias −= dl·Δt`, `ΔR_bias −= ds·ΔR` — 예측 ℓ,s 가 dl,ds 만큼 늘어나도록.

**σ 를 물리 스케일로 고정한 이유**: 처음엔 "4 bins" 로 고정했는데 coarse(30 m) 에서는 108 m, fine(10 m) 에서는 40 m 가
되어 30 m DEM 이 표현하는 지형 스케일(≥ 60 m) 을 fine 에서 지워버렸다 → 방위 ±10 px 진동. 120 m 로 고정하자
fine r_peak 0.15 → 0.28, 진동 소멸.

### 10-5. 반복 (`step03`)
```
coarse 27×16 bins (30 m), 탐색 ±25 bins → (dl, ds) → 반영 → 재시뮬 → 잔차 ≈ 0 확인 (닫힌 고리)
fine 9×5 bins (10 m), 탐색 ±12 → 서브빈 정밀화 2회 → 잔차
4분면 검사: 4개 영역에서 독립 추정 → 산포 (방위 0.5 m, 거리 1.4 m) → 상수 모델 성립
```
20250611: Δt = −0.449 ms (−2.86 px, 지상 −3.2 m), ΔR = +32.14 m, coarse r 0.44 / fine 0.28.

### 10-6. 창 단위 최소제곱 (`step07`) — 정식 추정
피크 1개는 불확도를 주지 못함. 씬을 1.8 km 창(60 bins @30 m, 50 % 중첩)으로 나눠 창마다 (ℓ_c, s_c, dl, ds, r) 를
얻고 (191 창), 강건 최소제곱:
```
상수:  dl = a0,  ds = b0
선형:  dl = a0 + a1·ℓ̃ + a2·s̃,  ds = b0 + b1·ℓ̃ + b2·s̃      ℓ̃, s̃ ∈ [−0.5, 0.5] 정규화
가중:  w0 = r²  (상관 높은 창 신뢰),  Huber IRLS: w = w0 · min(1, 1.345·ŝ/|e|),  ŝ = 1.4826·MAD(e), 10회
SE:    cov = σ̂² (XᵀWX)⁻¹
```
결과 (20250611): Δt = −0.423 ± 0.117 ms, ΔR = +32.94 ± 0.26 m. 선형항 t: 방위 along-track 1.9 (경계선), 나머지 < 1.5
→ 상수 채택. 창별 산포 RMS 방위 4.6 px / 거리 1.6 px 가 √191 로 줄어 SE 0.75 / 0.26 px.

**정합 스케일 실험**: 10 m bins → 창 30개·SE 5 px (DEM 정보 없음, 잡음만), 20 m → SE 0.9 px, **30 m → SE 0.75 px 채택**.
정합 격자는 DEM 해상도와 같아야 함.

## 11. 다중 씬 결합조정 — 센서 상수와 DEM 오프셋 분리

씬 i 에서 추정한 편향은 "센서 상수 + DEM 이 밀린 만큼" 이 섞인 값임. DEM 이 실제 지형에서 D = (dE, dN) 만큼
밀려 있으면 시뮬레이션이 그만큼 어긋나고, 그것이 씬 i 의 영상 좌표에서는

```
Δt_i = Δt_s + (D · â_i) / v_i               â_i: 씬 i 의 지상 방위 단위벡터 (E,N),  v_i = m_per_line/Δt (≈ 7076 m/s)
ΔR_i = ΔR_s + (D · r̂_i) · sin(inc_i)        r̂_i: 지상 거리 단위벡터 (근→원)
```
로 나타난다 (지상 이동을 방위 시각으로: /v, 슬랜트 거리로: ×sin inc). 상승/하강에서 â 가, 좌/우룩에서 r̂ 가 부호를
바꾸므로 D 와 (Δt_s, ΔR_s) 가 분리됨. 미지수 4, 관측 2×11, 가중 1/SE²:

```
결과:  ΔR_s = +31.15 ± 0.38 m,   Δt_s = −0.612 ± 0.239 ms (지상 −4.3 m)
       D = (동 +1.5 ± 0.9, 북 +4.8 ± 1.7) m        χ² 651 → 383 (자유도 2 추가; 6 이상이면 유의)
       단위분산 s0 = 4.6 → 씬별 잔차 RMS 방위 0.41 ms (≈2.9 m), 거리 1.26 m
```
s0 ≫ 1 은 씬별로 모델이 설명 못 하는 추가 오차 = **씬별 궤도 오차** 가 있다는 뜻이고 그 크기가 방위 ~3 m, 거리 ~1.3 m.
결과적으로 시계열 지오코딩에는 **씬별 편향** 을 쓴다 (공통 상수를 쓰면 이 3 m 가 씬 간 어긋남으로 남음).
그림 `step08_joint.png` 에서 상승(위)/하강(아래) 으로 Δt 가 갈리는 것이 D_N 의 지문임.

## 12. 지오코딩 (역방향) 알고리즘 (`step04`)

영상을 지도로 "밀어 넣는"(forward) 대신 지도 격자에서 영상을 "당겨 오는"(backward) 방식:
```
출력 격자 정의   EPSG:32652, res, 좌상단 (e0, n1) (res 배수로 스냅)
화소 중심마다    (E,N) → (φ,λ) → h_o = DEM(φ,λ), h = h_o + N_geoid → P = ECEF(φ,λ,h)
                (t, R, ℓ, s) = geo2rdr(P)        ← 씬별 편향 + 대류권 켠 모델
유효조건         0 ≤ ℓ ≤ n_avail−1,  0 ≤ s ≤ ncols−1
값 샘플링        멀티룩 강도 I_ml 에서 bilinear:  (ℓ/b_l − 0.5, s/b_s − 0.5)   ← 빈 중심 기준
dB = 10·log10(I)
```
장점: 구멍이 없고, 리샘플링이 한 번(강도 bilinear) 뿐이며, 각 출력 화소가 정확히 자기 DEM 높이로 위치됨.

**멀티룩 크기 자동 결정**: 출력 res 에 맞춰
```
b_l = round(res / m_per_line)          방위: 5 m / 1.11 = 4~5 라인
b_s = round(res · sin(inc_c) / ΔR)     거리: 5 m · sin32° / 1.0 = 3 샘플 (48.4 MHz 씬은 ΔR=2 m → 1)
```
씬마다 입사각·대역폭이 달라 룩 수가 다르지만 지상 크기는 ~5 m 로 같음.

**두 산출물**: 원본 dB (상대, DN² 기반) 와 필요 시 선형 `int = 10^(dB/10)`, `amp = sqrt(int)`. 보정상수가 없어 σ⁰ 가 아님.

## 13. 국지입사각·레이오버·그림자 (`step04.geocode`)

같은 루프에서 출력 화소마다:
```
DEM 법선 (UTM 격자 미터 단위):  n_enu = unit(−∂h/∂E, −∂h/∂N, 1) → ECEF
cosθ_loc = n_ecef · los,   locinc = arccos(cosθ_loc)
```
- **레이오버**: 지상 거리방향 단위벡터 d̂ (같은 ℓ 에서 s 증가 방향의 지도 벡터) 를 따라 s 가 **줄어드는** 곳:
  `∂s/∂ground = ∇s · d̂ < 0`. 물리적으로는 사면이 입사각보다 급해 꼭대기 에코가 바닥보다 먼저 도착하는 곳이고,
  이런 화소는 여러 지점이 섞여 있어 값이 해석 불가 → mask 1.
- **등돌린 면(그림자 후보)**: cosθ_loc ≤ 0 → mask 2. 차폐 계산은 하지 않았으므로 완전한 그림자 마스크는 아님.
- 255 = 자료 없음. 한라산 6 km AOI 에서 레이오버 2~7 %, 그룹 공통 유효화소 AR 45 % / ALDR 37 %.

## 14. 유효영역 외곽이 휘는 이유와 클립 (`step05`)

스와스 경계는 **슬랜트 거리** R0, R0+5.19 km 로 정의됨. 위성은 서쪽 상공 510 km, 32° 로 내려보므로 같은 R 에
도달하는 지상점은 땅이 높을수록 수평으로 더 멀다:
```
경계 이동 (원거리 쪽) ≈ h / tan(inc)          1400 m → 2.2 km,  1950 m → 3.1 km
```
실측: 유효영역 서/동 경계의 h=0 경계 대비 이동량 vs 그 지점 DEM 높이 → **r = 1.000, 기울기 1.57~1.62 (이론 1.56)**.
DEM 을 300 m·1 km 로 뭉개도 모양은 동일 (해상도 무관, 높이 때문). 방위 경계는 높이와 무관해 직선.
따라서 정사영상 유효영역은 사이드룩 SAR + 산악이면 반드시 지형 따라 휘며, 반듯한 산출물은
- 스트립 정렬 내접 직사각형 클립 (`step05`: 근거리 경계를 최대 이동량 + 50 m 안쪽으로; 20250611 폭 9.69 → 7.49 km), 또는
- 북향 AOI 타일 (`step04 --center --size`)
로 얻음.

## 15. 상대정합 검증과 네트워크 미세정합 (`step09`, `step10`)

**검증**: 같은 조명 그룹(AR / ALDR) 의 씬 쌍마다 지오코딩 타일을 30 m 로 낮춰 고역통과(σ 120 m) 후 마스크 상관 →
잔여 시프트 (dE, dN). 규약 `a(r,c) ≈ b(r−dr, c−dc)`, `dE = dc·res`, `dN = −dr·res`. 모델만의 결과: 20쌍 중앙 2.8 m,
RMS 5.2 m, 최대 11.1 m — 전체커버 씬끼리 ≤ 0.6 px, 큰 값은 부분커버·적설 3씬 관련.

**네트워크 최소제곱**: 미지수 씬별 시프트 s_i, 관측 `s_a − s_b = d_ab` (가중 r), 기준씬 `s_ref = 0` (강한 가중).
E, N 각각 풂. 잔차 rms 0.5~0.8 m (쌍 측정 잡음). 적용: `ndimage.shift(a, (dN/res, −dE/res))`, dB/locinc 는 bilinear +
유효도 가중 정규화(NaN 번짐 방지), mask 는 최근접. 재검증 중앙 0.6 m, 최대 1.1 m (0.22 px).

이 단계는 센서모델 오차를 데이터로 덮는 것이므로 절대위치 논의에는 원본을, 시계열에는 `_coreg` 를 씀.
